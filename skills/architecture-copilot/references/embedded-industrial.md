# 参考库 · 嵌入式与工业类

覆盖模板:`embedded-device` `iot-platform` `industrial-edge` `automotive-ee` `robotics`

---

### 嵌入式设备 / 固件系统 (`embedded-device`)
**关键决策**
- 裸机 vs RTOS:功能 ≤3 且无网络用裸机(时序易耦合),一旦「连接 + 业务 + 低功耗」并存就上 RTOS(几 KB~几十 KB 内存与心智代价)。
- 单分区 vs A/B 双分区 OTA:单分区省一半 Flash 但写一半断电即变砖;量产一律 A/B,几毛钱 Flash 成本远低于 0.1% 变砖召回。
- 本地 vs 云端算法:安全兜底必须本地(芯片贵、算法固化),体验增强可上云(断网即废)。
- 多硬件:单固件 + HAL + 板级配置表,避免分支版本爆炸。

**常见反模式**
- ISR 里做算法 / 发包 / 写 Flash(应只收数据发消息);喂狗放定时器(主逻辑死了狗照喂);OTA 无回滚(赌「测过不会失败」);运行期滥用 malloc 致碎片化;日志只靠串口(生产需黑匣子 + 回传);功耗留到最后优化(它是架构属性)。

**演进与触发信号**
- MVP 几十台裸机 / 轻 RTOS 先跑通传感器 → 执行器 → 小批量数千台上 RTOS + HAL + A/B OTA + 黑匣子 → 量产十万~百万台单固件多硬件、灰度 OTA + 熔断、崩溃回传、安全启动。升级信号:「这批开始收不回来了」是 OTA 与黑匣子的硬性触发点。

### 物联网平台 (`iot-platform`)
**关键决策**
- 直发指令 vs 设备影子:状态类走影子(设备醒来自对齐),动作类(重启 / 拍照 / 开门)走带 TTL 指令通道(直发离线即失败)。
- MQTT vs HTTP 轮询:设备通道用 MQTT 长连接(轮询费电费流量),掉线感知延迟约 1.5 倍心跳。
- 直连 vs 边缘网关:两者都支持,子设备也需独立身份。
- 遥测全存 vs 边缘预聚合:全量上云成本线性爆炸,预聚合降 10~100 倍但丢明细,分层按需采集。

**常见反模式**
- HTTP 轮询做设备通道(电池 / 流量不可持续);应用直连设备不管在线;遥测直写关系库(扛不住);全网共享一个接入密钥(破一台 = 破全部,应一机一密);升级全网一把推(无观察窗);重连不退避(恢复时集体冲锋压垮认证)。

**演进与触发信号**
- MVP 千台内用云 IoT 或单机 EMQX + 时序库跑通「连接 → 上报 → 下发」→ 成长期十万台补 OTA + 规则引擎 → 成熟期百万~亿级多地域、分层存储、平台化 OTA。升级信号:重连风暴、时序成本、影子抽象需统一。

### 工业边缘 / 数采系统 (`industrial-edge`)
**关键决策**
- 智能边缘 vs 云端:按「晚了会不会出事」切分,报警与现场响应必须边缘,分析 / 预测 / 优化放云端。
- IT 反向写 OT 权限:默认只读,写操作白名单化(限定测点范围 + 审批审计 + 边缘终审);全禁最安全但失远程调参价值,放开则云被攻破 = 产线被攻破。
- 协议归一层位置:必须在边缘归一,点位映射表是工业数字化最值钱的资产。
- 轮询频率:按测点重要性分级 + 死区过滤,「无扰」优先于「实时」。

**常见反模式**
- 车间网直连互联网(产线暴露,应分层隔离 + DMZ + 由内向外发起);报警链路依赖云(断网失能);IT 思维快速迭代 OT(控制系统不稳,应走停产窗口);轮询拉满把老 PLC 问死;点位映射散落各应用;断网数据直接丢弃(应缓存 + 断点续传)。

**演进与触发信号**
- MVP 单产线一台网关 + 现成软件 + 本地看板证明「采得上、不影响生产」→ 成长期全厂数万点网关集群 + 统一数据模型 + DMZ 改造 → 成熟期集团几十厂区边缘管理面 + 云端数据湖 + 预测性维护。升级信号:点位治理、报警风暴、断网自治。

### 汽车电子电气(E/E)架构 (`automotive-ee`)
**关键决策**
- 分布式 ECU vs 中央计算:100+ ECU 供应链成熟但软件散装、线束爆炸、OTA 难;域集中(4~6 域)为当前主流;中央 + 区域控制器线束省、OTA 顺但对车厂软件能力与冗余成本要求极高。
- 安全域 / 娱乐域隔离:物理隔离边界最硬但贵、跨域慢;Hypervisor 虚拟化省钱但需证明「娱乐崩绝不影响仪表」认证极贵。取向:关键显示独立兜底 + 大算力虚拟化。
- OTA:差分 + 灰度 + 失败率熔断是量产标配(全量简单但流量 × 百万辆)。
- 智驾数据:触发式为主,价值密度比数据量重要。

**常见反模式**
- 娱乐与控制混跑共享总线无隔离(车机死机波及刹车);OTA 不设安装条件行驶中重启(应 P 挡 + 电量 + 确认 + 回滚);拿互联网迭代套安全件;安全链路依赖平均性能(应看最坏情况用受控 CAN / TSN);车内网络默认互信;智驾数据先全存(成本爆炸)。

**演进与触发信号**
- 分布式 100+ ECU 供应商黑盒 → 域集中 4~6 域控(座舱智驾先自研 + 整车 OTA 就位)→ 中央计算平台 + 区域纯 I/O 按配置激活。升级信号:座舱迭代超单域能力、智驾成差异化、SKU 爆炸、线束成瓶颈、OTA 失败率需全局治理。

### 机器人系统 (`robotics`)
**关键决策**
- 智能放置:安全与运动闭环 100% 机上(算力有限、更新走 OTA),全局调度 / 多机协同 / 学习训练放云端(网络延迟威胁安全)。
- 通信:研发主体用 pub/sub(解耦、可回放、可仿真替换,有序列化开销),控制内环用共享内存 / 进程内直调(延迟最低但难录制)。
- 测试:仿真当 CI 门禁跑回归(有 sim-to-real 差距),实机做最终验收(真实但危险场景难测)。
- 多机:任务级中心调度 + 运动级本地避让。

**常见反模式**
- 急停依赖 Wi-Fi 或软件主链路(单点失效无法停,应安全旁路独立成环);相信单一传感器(轮速漂移必然,应多传感器融合 + 置信度);控制环与业务混跑(规划卡顿断流);仅实机测试;不做录制回放;把云当遥控器(断网即趴窝)。

**演进与触发信号**
- MVP 1~3 台 ROS 2 全栈跑通固定场景、安全旁路第一天就有 → 小批量 10~50 台打磨异常分支 + 车队平台(监控 / 远程接管) + 仿真库 + OTA → 规模化数百台中心调度 + 现场包 → 场景库 → 仿真 → OTA 闭环 + 多机地图协同。升级信号:自治率与人机比、运维成本决定生死、长尾收敛速度。
