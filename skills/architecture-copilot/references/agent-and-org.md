### Claude Code — 编码 Agent 的上下文与权限纵深防御 (`claude-code`)
**关键决策**
- 双层权限 + OS 沙箱 vs 单层指令约束:选前者(放弃简单性),因「凡模型指令能影响的层都不算硬约束」。
- 自动压缩 vs 手动上下文管理:选自动摘要 + 从磁盘重载 CLAUDE.md(丢失精确可控),铁律须写进 CLAUDE.md 而非对话记忆。
- 子代理轻量隔离 vs 继承全上下文:选独立窗口只回灌摘要(信息不全),避免主线被中间产物淹没。
- 工具 / MCP 延迟加载 vs 全量预载:选按需加载(可能漏工具),释放 50%+ 上下文预算。
- 本地优先会话 vs 云端共享:默认本地 JSONL(牺牲跨机共享),代码是核心资产留在本机。

**常见反模式**
- 安全指令只写 CLAUDE.md(会被提示注入绕过,硬边界须用 deny + 沙箱);CLAUDE.md 堆砌全部知识(常驻上下文膨胀挤垮任务空间);ask 规则配过多(弹窗疲劳致盲目批准);拿 Auto Memory 当事实源(会过时冲突,事实源永远是代码 + VCS)。

**演进与触发信号**
- MVP(个人单仓)→ 成长期(团队多仓,拆 Skills / Rules、接 MCP、加 Hooks、常态沙箱)→ 成熟期(组织级 CI、Agent SDK、多代理编排、审计落盘)。升级信号:上下文频繁撞窗口、规则难维护、需合规审计与权限分层治理。

### OpenAI Codex — 沙箱与审批正交的双形态编码 Agent (`codex`)
**关键决策**
- 沙箱与审批正交 vs 单维预设:拆成 sandbox_mode 与 approval_policy 两轴(心智负担更高),换取精确组合。
- 共享核心双执行形态 vs 分别实现:单 core 引擎 + 两套环境(本地 ≠ 云端体验),避免行为分叉与双倍维护。
- OS 内核级沙箱 vs 应用层自律:选 Seatbelt / bubblewrap + seccomp(平台相关、Windows 需 WSL2),防子进程逃逸。
- 默认离线 + 缓存搜索 vs 实时联网:默认拒网 + 域名白名单(联网需在 setup 阶段预置),防提示注入泄凭证。
- Rust 重写换长程稳定:单二进制、无 GC 停顿(代价:一次性重写迁移成本)。

**常见反模式**
- 以为非 danger-full-access 就是「受限 / 差」(workspace-write 覆盖约 99% 任务);混淆沙箱模式与审批策略(二者正交,一控物理边界一控中断时机);云端 agent 阶段期待联网 / 密钥(该阶段默认离线且移除凭证);把 AGENTS.md 当普通 README(它是就近生效的即时指令,子目录覆盖根目录)。

**演进与触发信号**
- MVP(read-only / on-request 建立信任)→ 成长期(可逆任务转 workspace-write、CI 用 exec + read-only + never)→ 成熟期(云端并行派发、产 PR 异步评审)。升级信号:人工审批(而非 agent 质量)成为瓶颈→转异步云端;任务成功率见顶→投入压缩与 auto_review 调优。

### OpenClaw — 单信任边界的自托管聊天网关 Agent (`openclaw`)
**关键决策**
- 自托管单进程守护 vs 云 SaaS:选前者(非多租户设计),前提「一个可信 owner + 一个本地进程」。
- 嵌入现有聊天平台 vs 自建客户端:选嵌入(让渡 UI 控制、继承平台信任边界),换零上手摩擦。
- 外包 agent 内核(Pi / ACP / codex 可插拔) vs 完全自控行为:换轻量与紧跟前沿。
- 技能编码为 SKILL.md 注入 XML:可经 ClawHub 低门槛共享(代价:装第三方技能 = 信任其内容)。
- 记忆存磁盘明文无隐藏态:选透明可审计而非黑盒全记。
- 双轨调度:Heartbeat(模糊触发 / 共享会话 / 不留任务记录,省 token) vs Cron(精确定时 / 隔离执行 / 留审计记录)——两条轴解决不同问题,别混用。

**常见反模式**
- 当多租户 SaaS 部署(违背单信任边界,应拆独立 gateway + 凭证甚至独立主机);默认放行 + 全工具开放(工具应默认 deny、显式白名单、敏感操作需审批 + 沙箱);以为记忆是「魔法黑盒」(模型只记它写入磁盘的内容);无差别装第三方技能(技能进系统提示 = 供应链风险,装即授权须逐一审查);混淆 Heartbeat 与 Cron(一个模糊省钱、一个精确留痕,用错场景);用弱模型驱动带工具的 agent(工具误操作风险放大)。

**演进与触发信号**
- 个人可信单机(默认宽松可接受)→ 多渠道 / 第三方技能(渠道 allowlist、群需 @bot、逐一审技能)→ 团队 / 对外暴露(拆信任边界:独立 gateway + 凭证 + 独立系统用户、最小工具集)。升级信号:接入非可信渠道或共享场景,别拿个人单机宽松默认套对外暴露。

### Hermes — 跑在 $5 VPS 上的单用户常驻记忆 Agent (`hermes`)
**关键决策**
- FTS5 关键词检索 vs 向量语义检索:选 FTS5(零外部依赖、CPU 友好、$5 VPS 可跑),代价是语义等价召回失败。
- 自动写技能自我进化 vs 稳定固化:换经验复利(代价:坏技能会被反复执行放大),靠命令审批 + 可观测 + 可中断而非硬沙箱。
- 统一守护进程 + 平台无关核心:单引擎服务 CLI / 网关 / IDE / cron(代价:守护进程成单点故障),单用户设计靠多 profile 隔离而非集群。
- 系统提示稳定不变:换前缀缓存高命中降本降延迟(代价:对话中途无法热加载新记忆 / 技能)。

**常见反模式**
- 当向量 RAG 记忆用(默认是 FTS5,语义召回弱);直接喂非可信用户 / 内容(会自动执行 + 自动写技能 = 把 shell 暴露给提示注入,须白名单 + 命令审批);当多租户 SaaS 横向扩容(单用户单部署,应多 profile / 多实例);放任记忆与自建技能(无自动 GC、技能会漂移,须定期人工审计裁剪)。

**演进与触发信号**
- MVP(仅自己、FTS5、本地终端)→ 成长期(多平台接入、收紧命令审批、隔离终端后端)→ 成熟期(语义 / 混合检索、Docker 全隔离、定期记忆技能审计)。升级信号:语料变大语义鸿沟扩大、危险命令需管控、记忆膨胀无 GC。

### 系统提示词架构 — Agent OS 的六层分层提示设计 (`system-prompt-architecture`)
**关键决策**
- 模块边界策略:XML 命名空间标签(可 grep、层级优先) vs Markdown 标题(人友好但作用域松、易冲突) vs 工程指令块(任务对齐但可移植性差)——「边界比语法更重要」。
- 能力放置:全内联(可读但 token 膨胀) vs 摘要 + 外部 SKILL.md(可扩展但需强制 view)——超约 3 个能力域即外置。
- 合规实现:软提示「请不要」(快但非确定) vs 提示 + 后处理流水线(可审计)——版权字数 / 儿童安全 / 机制泄露等红线必须走后处理。
- 工具发现:全部约 27 个 schema 常驻 vs tool_search + 懒展开(省 token 但可能漏工具)。
- 记忆注入:自然语言禁语表(软、可读但非确定) vs 显式记忆工具(结构化、可审计)——关键约束别只靠禁语表。
- 人格范围:单一 constitution 保品牌一致 vs 多人格灵活——「安全层永不分叉」。

**常见反模式**
- 把系统提示当人格脚本(应先画六层图再加语气);安全规则散落各工具段(合规碎片化难审计,应集中并写明覆盖规则);用「请不要」软约束防伤害(须硬拒绝 + 原则声明 + 分类器流水线);从公开文章复制示例(提示自身变侵权);假设 MUST-NOT 一定被执行(关键红线需后处理 linter + 测试套件)。

**演进与触发信号**
- MVP(单产品少工具、单人格 + 基础安全,别过度模块化)→ 成长期(联网 + 文件 + 10+ 工具,模块化块 + 工具注册表 + 基础版权)→ 成熟期(六层 Agent OS + 外部 Skills + 运行时注入 + 合规流水线 + 决策树)。升级信号:模块冲突、人格分叉治理、注入面扩大、需评估门禁。

### AI 原生组织 / 流程架构 — 把 AI 从个人工具升级为组织级生产系统 (`ai-native-organization`)
> 说明:该模板是专题入门索引(章节路线图),非传统 14 节系统模板,故按原文核心决策忠实提炼。

**关键决策**
- 个人工具 vs 组织系统:「人人配一个 AI 工具」≠ AI 原生组织,须改造成人与 Agent 共享上下文、可审查交付、可持续学习的生产系统。
- 超级个体 vs 超级团队:AI 放大个人后,团队仍重要(人才密度 vs 组织摩擦)。
- 共享上下文即组织接口:PRD、ADR、任务、trace、复盘让人和 Agent 读同一份事实。
- 个人技巧 vs Golden Path:个人 prompt 技巧须沉淀为模板、Skill、Flow 和默认路径。
- 责任治理:AI 可参与但责任不能悬空,需权限、审查、审计、激励。

**常见反模式**
- (原文未单列反模式章节)核心警示:误把「人人用 AI」当作组织 AI 原生,导致责任悬空、个人技巧无法沉淀。

**演进与触发信号**
- 全景演进:愿景共识 → 价值流小队 → 共享上下文 → AI 工作层 → 治理层 → 交付反馈循环;路线为 MVP → 成长期 → 成熟期,从 3–5 人试点到组织级 AI 操作系统。升级信号:(原文未单列具体触发清单)由试点规模扩展到组织级即进入下一阶段。
