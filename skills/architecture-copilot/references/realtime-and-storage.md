# 参考库 · 实时、协同与存储类

覆盖模板:`realtime-chat` `collaborative-doc` `cloud-storage` `video-streaming`

---

### 实时聊天系统 (`realtime-chat`)
**关键决策**
- 长连接扩展:单机纵向(有天花板 / 单点) vs 水平扩展 + 用户↔网关路由表(取后者,有状态服务扩展通用套路)。
- 群扩散:小群写扩散 vs 大群共享读取(只存一份、按已读位点拉取,避免万人群瞬时上万次投递)。
- 可靠投递:裸发(会丢 / 重) vs ack + 重试 + 幂等去重 + 先落库再投递。
- 在线状态:强一致(巨大浪费) vs 最终一致 + 内存 KV + TTL。

**常见反模式**
- 用轮询代替长连接(慢且费);按到达顺序展示而非会话内单调序号(乱序);重试不去重(重复);把连接当无状态路由(必须有路由表);media 字节塞消息流(应存对象存储只带引用)。

**演进与触发信号**
- MVP(几万):单机长连接 + 序号 / ack / 离线,做对「实时不丢有序」。成长(百万连接):分布式网关 + 路由表、消息存储分片。成熟(千万):大群共享读取 + 多活多区域 + E2EE。升级信号:连接数逼近单机上限、大群涌现、需容灾合规。

### 多人协同文档 (`collaborative-doc`)
**关键决策**
- 并发合并:锁(实现简单但排队,体验灾难) vs OT(主流,需中心定序) vs CRDT(适合离线去中心,元数据开销);核心是「保留意图而非覆盖」。
- 操作处理:多节点乱序 vs 同文档路由到单一 writer 串行(把并发转为顺序)。
- 传输:同步整文档 vs 只传增量操作(几字节)。
- 存储:只存最新快照 vs 操作日志 + 定期快照(兼顾回溯与快速加载)。

**常见反模式**
- 「最后保存者覆盖」处理多人编辑(丢意图);用锁实现「协同」(那是排队);同文档被多节点乱序处理;每次改动同步整文档;只存快照丢历史(失去版本与审计)。

**演进与触发信号**
- MVP(单文档少数人):中心 OT + WebSocket + 日志,跑通「两人同时编辑不打架」。成长(多团队):分片、presence、离线同步、权限。成熟(跨区域):CRDT 或强化 OT、超大文档分块、富内容、端到端安全。升级信号:海量长连接、超热文档、操作日志膨胀。

### 云存储 / 网盘 (`cloud-storage`)
**关键决策**
- 存储粒度:整文件(简单但改一字重传、无续传、重复存) vs 分块(必然选,续传 / 增量 / 去重 / 并行都是副产品)。
- 块寻址:随机 ID(重复存) vs 内容哈希寻址(去重成为存储自然属性)。
- 元数据与内容:混存(两头不讨好) vs 分离(按访问形态选存储)。
- 同步冲突:后覆盖前(丢数据) vs 保留冲突副本(绝不静默覆盖)。

**常见反模式**
- 整文件传输、改一字重传;元数据与内容混在一种存储;同步冲突直接覆盖;相同文件 / 块存多份;大文件不做断点续传。

**演进与触发信号**
- MVP:整文件 + 简单元数据库,跑通上传下载多设备可见。成长(百万用户):分块、增量、去重、断点续传、版本、回收站。成熟(海量 / 企业):端到端加密、跨区域、冷热分层、CDN、协作管控。升级信号:元数据膨胀、内容规模、同步通知扇出、热点文件下载压力。

### 视频流媒体 (`video-streaming`)
**关键决策**
- 转码时机:同步(卡住上传、抢算力) vs 异步队列 + 弹性工作集(必须,重计算移出请求路径)。
- 码率档位:少(省算力但弱网差) vs 多(贴合但成本翻倍),取覆盖主流网络屏幕的有限档。
- CDN:按需回源(简单但首用户慢 / 易惊群) vs 主动预热(需预测),冷长尾按需、头部热门预热。
- ABR 决策权:服务端(难感知网络) vs 客户端(最清楚本地缓冲,取客户端);点播与直播通常需不同链路。

**常见反模式**
- 不转码直发源片;从源站直发不上 CDN(带宽爆炸、源站被打垮);同步转码卡上传;定死一档不做 ABR;整片当大文件下发(应切片 + 清单);热门也按需回源;视频字节与元数据混存。

**演进与触发信号**
- MVP:单档码率 + 直接分发,先验证有没有人看。成长(百万播放):多码率异步转码管线 + CDN + ABR,盯卡顿率 / 命中率。成熟(千万~亿级):全球多 CDN + 分层缓存 + 直播低延迟链路 + DRM。升级信号:转码算力堆积、CDN 命中率与带宽成本、热门内容惊群。
