# 架构术语表(核心速查)

> 每条只给一句话直觉,秒懂它在说什么。

## 规模与性能
- **QPS / TPS**:每秒请求数 / 每秒事务数,衡量系统多忙。
- **延迟(Latency)**:单次操作要等多久。
- **吞吐(Throughput)**:单位时间能处理多少。
- **P99(尾延迟)**:99% 的请求比这个值快;看 P99 别看平均,最慢的 1% 最伤体验。
- **读写比**:读多还是写多,决定往「读优化」还是「写优化」倾斜。
- **信封背面估算**:用几个除法快速估出数量级(QPS、存储量),判断系统会被什么压垮。

## 数据与一致性
- **强一致 / 最终一致**:写完立刻全网都对(贵) / 写完过一会儿才一致(便宜、高可用)。
- **CAP**:网络一旦分区,只能在「一致」和「可用」里二选一。
- **ACID / BASE**:严谨派(强一致、强保证) / 务实派(高可用、最终一致)。
- **事务(Transaction)**:一组操作要么全成、要么全不成。
- **幂等(Idempotency)**:同一操作重复执行多次,结果和执行一次一样,重试不会闯祸。
- **无状态 / 有状态**:不记事(好复制好扩) / 记事(难复制,一切麻烦的根)。

## 扩展手段
- **垂直扩展 / 水平扩展**:把单机搞更强(有上限) / 加更多机器(要求无状态)。
- **复制(Replication)**:做多份只读副本,主要为「扩读」。
- **分片(Sharding)**:按规则把数据切到多台机器,主要为「扩写」。
- **缓存(Cache)**:把热点数据放更快的地方,降延迟 + 扩读,代价是一致性。
- **CDN**:把内容铺到离用户最近的边缘节点,降延迟 + 省带宽。
- **削峰 / 限流**:用队列 / 排队把瞬时洪峰整形成平缓水流,别让后端被冲垮。

## 架构模式
- **单体 / 微服务**:一个部署单元(简单) / 多个独立部署的小服务(解决「人」的扩展,常被滥用)。
- **事件驱动 / Pub-Sub**:广播「发生了什么」,谁关心谁响应,解耦与扇出。
- **CQRS**:把「写」和「读」拆成两套模型各自优化。
- **扇出(Fan-out)**:一件事触发很多下游,推模型(写时扇出) vs 拉模型(读时聚合)。
- **倒排索引**:把「文档→词」翻转成「词→文档列表」,全文检索的根基。
- **ANN(近似最近邻)**:用一点精度换巨大速度,在海量向量里快速找「最相似」。

## 可靠性与运维
- **可用性 / 几个 9**:系统有多少时间是活着的;99.9% = 3 个 9,每多一个 9 成本数量级上涨。
- **持久性(Durability)**:存进去的数据丢失概率有多低(如 S3 的 11 个 9)。
- **SLO / 错误预算**:给可用性定目标(SLO),剩下的不可用额度就是错误预算,用完就停新功能保稳定。
- **单点故障(SPOF)**:某处一挂全系统瘫,可用性的头号敌人,靠冗余消灭。

## 流程与演进
- **质量属性 / 非功能性需求**:系统「做得多好」(快 / 稳 / 扛得住),区别于「做什么」。
- **取舍(Trade-off)**:任何决策都是用 A 换 B,没有银弹。
- **ADR**:架构决策记录,用一页纸记下为什么这么决定、放弃了什么。
- **技术债**:为「现在更快」有意识选的权宜方案,关键是记账、按计划还。
- **康威定律**:系统架构会长得像设计它的组织的沟通结构。
- **C4 模型**:像地图缩放一样分四层画架构图:Context → Container → Component → Code。
